# Codex Reset Monitor

`codex-resets.com`의 공개 API와 로컬 Codex 계정의 실제 주간 사용량을 조회하고 리셋 변화를 Telegram으로 알립니다.

## 알림 조건

- 리셋 목록에서 새로운 리셋 ID가 발견된 경우.
- 새로운 `scheduled_reset.id`가 발견된 경우.
- 새로운 `active_watch.observed_at`이 발견된 경우.
- watch 단계가 `elevated`에서 `strong`으로 상승한 경우.
- 동일 watch의 확률이 직전 상태보다 20%p 이상 상승한 경우.
- 같은 리셋에 원문 또는 관련 링크가 나중에 추가된 경우.
- 같은 리셋의 종류가 `regular`과 `banked` 사이에서 변경된 경우.
- 로컬 Codex 계정의 주간 사용률이 15%p 이상 감소한 상태가 20초 간격으로 두 번 확인된 경우.
- 사용률이 이미 낮더라도 새 주간 사용량 창이 시작된 상태가 20초 간격으로 두 번 확인된 경우.
- 로컬 Codex 계정에 사용 가능한 banked reset 크레딧이 추가된 경우.

첫 실행에서는 기존 이벤트를 알리지 않고 현재 값을 `state.json`에 저장합니다. 이후 Telegram 전송이 성공한 경우에만 새 상태를 저장합니다.

공식 X 발표 없이 관측된 리셋에 링크가 없으면 2분 동안 보강을 기다립니다. 2분 이내에 링크가 생기면 링크를 포함해 알리고, 계속 없으면 링크 없음으로 알립니다. 알림 후 링크가 추가되면 기존 Telegram 메시지에 답장합니다. 발표 또는 감지 시각만 수정된 경우에는 알리지 않고 상태만 갱신합니다.

리셋 발표 시각과 watch 만료 시각은 API 원문의 UTC와 변환된 KST를 함께 표시합니다.

`state.json`은 실제 리셋과 예정 발표 ID별 Telegram 메시지 ID와 연결 상태, 처리한 최신 발표 시각을 저장하며 완료·만료 상태는 각각 최신 50건만 유지합니다. 계정 사용량 관측값과 판정 결과는 최신 20건만 유지합니다. API에서 과거 항목이 삭제되거나 다시 나타나더라도 처리한 최신 시각 이전의 리셋은 알림 없이 상태에 반영합니다. 아직 알리지 않은 대기 상태는 정리 대상에서 제외됩니다. 프로그램은 파일 잠금으로 같은 실행 디렉터리에서 한 인스턴스만 동작합니다.

`scheduled_reset`은 먼저 리셋 예정 메시지로 알리고 실제 계정 반영을 기다립니다. 계정 리셋이 나중에 확인되면 예정 메시지에 답장합니다. 계정 리셋이 먼저 확인된 경우에는 즉시 독립 알림을 보내고, 뒤늦은 예정 발표의 `scheduled_for`가 실제 사용량 창 시작 시각과 2시간 이내일 때 기존 계정 메시지에 답장합니다. 예정 발표가 먼저면 발표 시각 1시간 전부터 예정 시각 36시간 후까지 계정 반영을 연결할 수 있습니다. 후보가 둘 이상이면 자동 연결하지 않으며, 예정 시각 36시간 후까지 계정 반영이 없으면 알림 없이 만료합니다.

## 사용자 계정 조기 감지와 공식 발표 매핑

계정 사용량은 현재 로그인된 로컬 `codex` CLI의 app-server를 통해 읽습니다. 토큰을 직접 읽거나 저장하지 않으며 `state.json`에는 계정 ID 원문 대신 SHA-256 기반 지문만 저장합니다. 첫 계정 조회와 계정, 플랜, 제한 ID 변경은 기준선만 저장하고 알리지 않습니다.

계정 리셋은 두 가지 독립 신호로 판정합니다. 첫 번째는 주간 사용률이 15%p 이상 감소한 경우입니다. 두 번째는 `resets_at`에서 사용량 창 길이를 뺀 새 창 시작 시각이 현재 관측 시각 근처이고, 다음 리셋 시각이 미래로 이동했으며, 현재 사용률이 5% 이하인 경우입니다. 어느 신호든 발견하면 20초 뒤 다시 확인하고 유지될 때 알립니다. 재확인 중 `resets_at`이 조금 조정돼도 같은 새 창 범위이면 후보를 유지합니다. 예정 시각의 정상 갱신도 실제 계정 초기화로 확인되면 알립니다.

banked reset 크레딧이 감소한 뒤 5분 동안 발생한 사용률 감소는 사용자가 크레딧을 사용한 것으로 보고 일반 리셋 알림에서 제외합니다. 크레딧 지급과 regular 초기화 신호가 동시에 발생하면 두 이벤트를 독립적으로 처리합니다.

계정 감지와 공식 발표의 종류가 같고, 공식 발표 시각이 계정 감지 36시간 전부터 24시간 후 사이이며, 양쪽에 매핑 가능한 후보가 정확히 하나일 때만 같은 리셋으로 연결합니다. 계정 감지가 먼저면 이후 공식 링크를 원래 메시지에 답장하고, 공식 발표가 먼저면 계정 반영 확인을 발표 메시지에 답장합니다. 같은 조회에서 함께 확인되면 메시지 한 건으로 합칩니다. 예정 발표, 계정 리셋, 실제 리셋 결과가 모두 확인되면 세 ID를 같은 그룹에 상호 저장합니다. 후보가 둘 이상이면 잘못 연결하지 않도록 자동 매핑하지 않습니다.

app-server 조회 실패는 해당 주기의 계정 감지만 건너뛰며 기존 공개 API 감시는 계속합니다. 반대로 codex-resets.com이 실패해도 로컬 계정 감시는 계속합니다. 후보 생성, 재확인, 확정, 취소 및 banked 제외 결과는 최근 관측 이력에 기록됩니다. 이 RPC는 설치된 Codex CLI 버전의 app-server 프로토콜에 의존하므로 CLI 업데이트 후 통합 테스트로 호환성을 확인하는 것이 좋습니다.

## 실행

```bash
cp .env.example .env
# .env에 실제 봇 토큰과 채팅 ID를 입력합니다.
go run .
```

프로그램은 실행 디렉터리의 `.env`를 자동으로 읽습니다. 시스템 환경변수와 `.env`에 같은 키가 있으면 시스템 환경변수를 우선합니다. `.env`는 Git에서 제외됩니다.

계정 사용량 감시는 기본으로 활성화됩니다. 비활성화하려면 `CODEX_USAGE_MONITOR_ENABLED=false`를 설정합니다. `codex`가 PATH에 없다면 `CODEX_BINARY`에 실행 파일 경로를 지정합니다. 모니터를 실행하는 OS 사용자에게 Codex 로그인이 되어 있어야 합니다.

바이너리는 다음 명령으로 만들 수 있습니다.

```bash
go build -o codex-reset-monitor .
./codex-reset-monitor
```

`state.json`은 실행한 디렉터리에 생성되며 Git에서 제외됩니다.

## 테스트

```bash
go test ./...
```

실제 Telegram을 보내지 않고 로컬 Codex 계정 사용량 RPC만 확인하려면 다음 명령을 실행합니다.

```bash
CODEX_USAGE_INTEGRATION_TEST=1 go test -run '^TestCodexAccountUsageIntegration$' -v
```

실제 Telegram을 보내지 않고 codex-resets.com의 `scheduled_reset` 응답 호환성만 확인하려면 다음 명령을 실행합니다.

```bash
CODEX_RESETS_INTEGRATION_TEST=1 go test -run '^TestCodexResetsScheduledIntegration$' -v
```

실제 Telegram으로 네 단계 테스트 알림을 보내려면 다음 명령을 실행합니다. 링크 있는 리셋, 링크 없는 리셋, 다음 리셋, 이전 링크 없는 리셋에 대한 답장 순서로 전송됩니다.

```bash
TELEGRAM_INTEGRATION_TEST=1 go test -run TestTelegramNotificationFlow -v
```
